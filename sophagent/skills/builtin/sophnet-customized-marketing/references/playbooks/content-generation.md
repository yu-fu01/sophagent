# Content Generation Playbook

使用场景：
- 用户说“帮我搞个推广”“写条朋友圈”“帮我写个群发话术”“写个小红书文案”
- 用户当前目标是生成单个渠道的营销内容

如果用户要“策划一个XX活动”“搞个促销方案”（整体活动设计），改读 `references/playbooks/campaign-planning.md`。
如果用户要“所有渠道都发一遍”“每个平台都来一版”，改读 `references/playbooks/multi-channel-bundle.md`。

## 工作流

### Step 1. 采集上下文

先完成三件事：

1. 读取老板风格档案：见 `references/playbooks/style-profile-workflow.md`
2. 获取业务数据：按 SKILL.md Quick Start 中的业务数据获取规则，通过 agent 编排调用相关 skill
3. 确认营销目标：推什么、发到哪、给谁看

降级策略：若用户未安装相关 skill，直接追问：

- “你主推什么产品？大概什么价位？”
- “你的客户主要是哪类人群？”
- “最近有什么想推的活动吗？”

### Step 2. 热点与节日检查

先参考 `references/marketing-date-checklist.md`，确认近期 2 周内有无节日、电商节点、节气可借势。

对日期不固定的节点，用搜索确认：

```text
web_search "[当前年份] [节日名] 日期"
web_search "[当前年份] 放假安排"
```

热点趋势可选：

```text
web_search "今日热搜"
web_search "[行业关键词] 最新动态"
web_search "[行业关键词] 热门话题"
```

- 如需细节，再用 `web_fetch` 查看具体页面
- 只保留与用户业务相关的热点
- 热点失败不阻塞流程，可直接用业务数据 + 节日节点继续

### Step 3. 客群分析

如果拿到了客户数据，根据行业和字段结构动态分群：

- 花店：消费频次 + 偏好花种
- 保险：保单到期时间 + 险种
- 美容院：项目类型 + 到店周期
- 蛋糕店：消费频次 + 订单类型
- 无法判断行业时：消费频次 + 最近互动时间 + 标签

输出时必须体现：

- 客群名称
- 分群依据
- 客群人数
- 该客群的利益点、语气、CTA 差异

不同客群的文案要有实质差异，不能只改称呼。

### Step 4. 先给营销方案摘要

先不要直接长篇生成，先给方案摘要，等用户确认：

```text
已为你准备 [节日/活动] 营销方案：
· 目标客群：[分群结果]
· 推荐主推产品：[产品名(库存状态, 价格)]
· 可借势热点：[热点/节日]
· 建议渠道：[朋友圈/微信群/小红书/公众号]
· 建议发布时间：[时间及原因]

需要生成文案吗？
```

### Step 5. 确认风格并生成文案

在动笔前，必须确保已持有老板风格偏好。若尚未建档，按 `references/playbooks/style-profile-workflow.md` 先完成建档。

生成文案时必须满足：

- 真实产品信息来自库存数据或用户口述
- 有明确 CTA，如“私信预定”“扫码下单”“评论区留言”
- 融入老板个人风格

禁止事项：

- 编造产品、价格、电话、地址等具体信息
- 使用明显 AI 套话，如“首先/其次/最后”“总而言之”
- 与风格档案冲突

平台写法要求见 `references/platform-writing-guidelines.md`。

### Step 6. 建议是否配图

文案完成后，不自动生成图片，而是先建议配图方案：

```text
建议配图方案：
1. 朋友圈海报 (1080×1080) — 促销风，突出 [产品] + 价格
2. 微信群分享图 (500×400) — 同主题简化版

是否需要生成？可以全部生成，也可以选择部分。
```

若用户确认，再读 `references/playbooks/poster-generation.md`。

### Step 7. 持续学习风格

如果用户对风格提出反馈，在完成本轮修改的同时更新风格档案，做法见 `references/playbooks/style-profile-workflow.md`。

## 输出要求

- 单渠道时只输出当前目标渠道版本，不要顺手附带其他平台
- 文案必须是可直接发的成品，不要只给提纲
- 生成完成后，自检 `references/quality-checklist.md`
- 文案安全红线见 `references/content-safety.md`
