项目定位

参考开源项目 hermes-agent（45 万行级）的核心设计，以约 1% 的代码量实现其关键能力。

需求实现方式
第三方 OpenAI / Anthropic 模型Provider 抽象层：任意 OpenAI 兼容 API（可配 base_url）+ Anthropic 原生 API；API key 只存配置文件，不入库；已适配 DeepSeek 思考模型（reasoning 回传）
多 Agent / 多会话 / 高并发管理员定义多个 Agent（提示词 / 模型 / 工具白名单 / Skill 白名单）；单进程 asyncio + 会话级锁 + 全局并发信号量；支持 delegate_task 子 Agent 委派
自进化能力Skill 索引注入系统提示，Agent 运行时通过 skill_manage 自主创建 / 改进 / 删除 Skill（与 hermes 的 SKILL.md 格式兼容）
多用户与权限JWT 登录，admin / user 两级角色；会话、工作目录、长期记忆全部按用户隔离；管理员增删用户（级联清理数据）
轻量化每轮对话「从库加载 → 运行 → 释放」，无常驻 Agent 实例；前端为零依赖单文件 HTML
容器化python:3.12-slim 单阶段构建，非 root 运行，/data 卷持久化，自带健康检查

核心流程：一轮对话

1请求进入校验 JWT 与会话归属，取会话锁、过全局信号量
2组装上下文系统提示 = Agent 提示词 + Skill 索引 + 用户记忆 + 环境信息；超限则压缩
3调用模型流式返回，文本增量实时经 SSE 推给前端
4执行工具模型发起工具调用 → 注册中心调度（超时 / 截断 / 白名单）→ 结果回填
5循环或结束有工具调用回到第 3 步（≤ max_iterations）；每条消息实时落库
⟲ 自进化闭环：Agent 在第 4 步可调用 skill_manage 把「学到的可复用流程」写成 SKILL.md → 下一轮系统提示的 Skill 索引立即包含它 → 所有 Agent、所有用户共享受益；管理员可在 Web 界面审查或删除。

API 一览

方法路径权限说明
POST/api/auth/login公开用户名密码 → JWT
GET / POST / PATCH / DELETE/api/usersadmin用户管理（删除级联清理数据）
GET / POST / PUT / DELETE/api/agents读 user · 写 adminAgent 定义管理
GET / POST / DELETE/api/sessionsuser（仅本人）会话管理
POST/api/sessions/{id}/chat本人SSE 流：text_delta / tool_call / tool_result / done
POST/api/sessions/{id}/stop本人中断正在运行的回合
GET / PUT / DELETE/api/skills读 user · 写 adminSkill 库审查通道
POST/v1/chat/completionsBearer JWTOpenAI 兼容；model = Agent 名；支持 stream
GET/v1/modelsBearer JWT列出全部 Agent

使用方式

① 一键部署 
cp .env.example .env     # 设置 ADMIN_PASSWORD；模型配置写 data/providers.yaml
docker compose up -d --build
# 浏览器打开 http://localhost:8000，用 admin 登录
② 模型接入（data/providers.yaml） 
providers:
  sophnet:                      # 任意名字，Agent 定义里引用
    api_mode: openai            # openai = 一切 OpenAI 兼容 API；另支持 anthropic
    base_url: https://www.sophnet.com/api/open-apis/v1
    api_key: sk-...
    context_limit: 64000
③ 日常使用流程
1admin 在管理面板创建 Agent（选模型、勾选工具）并添加用户
2用户 登录 → 新建会话 → 选 Agent → 聊天（支持 Markdown 富文本渲染）
3程序 通过 OpenAI SDK 直连：base_url="http://host:8000/v1"，api_key 填 JWT
4admin 定期在 Skills 卡片审查 Agent 自建的知识

安全边界与已知取舍

事项说明
容器是硬隔离边界终端 / 代码执行钉在用户工作目录、环境变量白名单、超时与输出限额；容器内多用户之间为软隔离，多租户敏感场景应禁用终端类工具或按用户拆分容器
SSRF 防护网页抓取拒绝解析到内网 / 回环地址的目标
Skill 注入风险自建 Skill 进入系统提示，存在被诱导写入误导内容的可能 → 管理员审查通道兜底
SQLite 写上限WAL 支撑数十并发会话；更重负载时数据层已收口，可平移 Postgres
